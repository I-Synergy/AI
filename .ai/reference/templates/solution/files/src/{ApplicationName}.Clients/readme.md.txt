# {ApplicationName}.Clients

Strongly typed client for `{ApplicationName}.Service.Api`, generated by Kiota.

- `Api/` holds the generated files. They are committed so the solution builds from a fresh checkout without running the generator. The shipped copies are the output for the sample `{Entity}` API; the Debug build of `{ApplicationName}.Service.Api` regenerates them from `openapi/{ApplicationName}.Service.Api.json`.
- Build order: this project references the API project with `ReferenceOutputAssembly="false"`, so the API's Debug build (and the generation) completes before this project compiles. This removes the fresh-checkout ordering problem without an assembly dependency.
- The compile list of `Api/` is read from disk at compile time, so a route change that adds or removes generated files is compiled after the next Debug build.
- Release builds do not regenerate. They compile the committed files, so commit the regenerated files after a route change.
- `kiota-lock.json` is written by the generator and is not shipped as a template.
- Member and `using` order follows Kiota's alphabetical sort, so a name whose sort position differs from the sample `Item` reorders the generated members on the first Debug build. The code does not change.
- Do not edit `Api/` by hand. To skip regeneration, pass `-p:{ApplicationName}GenerateApiClient=false` to the API build.
- Registration in dependency injection belongs to the consuming application project, not to this one.
